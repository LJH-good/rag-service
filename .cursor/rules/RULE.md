## 공통 코드 변경 규칙

- **변경 범위 최소화**
  - 불필요한 리팩토링(이름만 변경, import 정리만 하는 대규모 변경 등)은 피합니다.
  - 하나의 작업에서는 **하나의 목적(기능 추가, 버그 수정 등)** 에 집중합니다.

- **예외 처리**
  - 비즈니스/도메인 에러는 **공통 예외 타입 + 공통 에러 코드**(예: `AppException + ErrorCodes`)를 우선 사용합니다.
  - 새 예외를 추가할 때는 기존 코드에서 쓰는 **메시지·필드명·로그 포맷**을 최대한 따릅니다.
  - 예외를 조용히 삼키지 말고, 로깅 후 상위 레이어로 전달하거나 공통 핸들러가 처리할 수 있게 유지합니다.

- **로그 작성**
  - 운영에서 추적 가능한 **키 값(예: transactionId, jobId, userNo 등)** 을 로그에 포함하는 것을 우선합니다.
  - 기존 로거 prefix 형식(예: `[RAG]`, `[RAG_SM]` 등)을 가능한 한 유지합니다.
  - 동일 예외를 여러 단계에서 중복 로그하지 않도록, 로그 위치를 최소/핵심 지점으로 제한합니다.

- **테스트**
  - 서비스/비즈니스 로직(`*Service`, 상태 머신, 계산 로직 등)을 수정하면 **단위 테스트를 함께 수정/추가**합니다.
  - 버그 수정 시에는 **재발 방지용 회귀 테스트**를 최소 1개 추가합니다.
  - 테스트 메서드 이름은 “상황 + 기대 결과”가 드러나게 작성합니다. (예: `ask_whenEmbeddingIsEmpty_throwsAppException`)

- **API/컨트롤러**
  - 외부에 공개된 API(Controller, REST endpoint)의 **URI, HTTP Method, 필수 헤더/파라미터**는 임의로 변경하지 않습니다.
  - 스펙 변경이 필요하면 기존 스펙을 깨지 않는 방향(옵션 필드 추가, 신규 엔드포인트 추가)을 우선 검토합니다.
  - 요청/응답 DTO 변경 시, **문서(Swagger, MD 등)** 와 **연관 테스트**를 함께 갱신합니다.

- **성능·쿼리**
  - DB 쿼리·외부 연동·루프 내부 네트워크 호출처럼 비용이 큰 작업을 추가할 때는 **대략적인 비용/호출 빈도**를 고려합니다.
  - N+1, 불필요한 전체 조회 등 명백한 비효율이 보이면 함께 개선을 검토합니다.

- **스타일·포맷**
  - 포맷팅은 IDE/프로젝트 설정(예: Google Style)에 맡기고, 수동 정렬/줄바꿈은 최소화합니다.
  - 주석은 “무엇을 한다”보다는 **“왜 이렇게 하는지”** 가 필요한 부분에만 작성합니다.

- **구성/설정 변경**
  - 포트, 타임아웃, 리소스 제한, 스토리지 경로 등 운영에 영향을 줄 수 있는 설정을 바꿀 때는:
    - 변경 이유를 코드나 커밋 메시지에 짧게 남기고,
    - 기본값을 크게 다르게 바꾸지 않도록 합니다.

## 주석 규칙

- **기본 원칙**
  - 코드는 “무엇을 하는지”가 드러나도록 작성하고, 주석은 주로 **“왜 이렇게 하는지”**를 설명합니다.
  - 구현 세부를 그대로 반복하는 주석(예: `// 리스트를 순회한다`)은 작성하지 않습니다.

- **클래스 / 메서드 주석**
  - 공개 API나 주요 서비스/워커 클래스에는 가능하면 **Javadoc 형식**을 사용합니다.
    - 한글 기준: 역할, 주요 흐름, 중요한 정책/제약 위주로 짧게 작성합니다.
  - 메서드 Javadoc에는 필요할 때만 `@param`, `@return`, `@throws`를 사용합니다.

- **블록 주석 (로직 설명)**
  - 비즈니스 규칙, 상태 전이, 예외적인 분기 등 **읽으면서 헷갈릴 수 있는 부분**에만 작성합니다.
  - “이전/다음 단계”, “재시도 정책”, “에러 시 처리 방식”처럼 **정책성 설명**을 우선으로 씁니다.

- **로그와 연계된 주석**
  - 로그 prefix나 key가 중요한 경우(예: `[RAG]`, `[RAG_SM]`)는, 변경 시 꼭 지켜야 할 포맷을 주석에 한 줄로 남깁니다.
  - 예: `// 로그 포맷: [RAG][txId] embed ok. dim={}, ms={}`

- **언어/형식**
  - 도메인/업무 설명은 **한글**을 우선 사용합니다.
  - 외부 라이브러리 제약, 프로토콜 스펙 등은 필요하면 영어로 그대로 인용합니다.
