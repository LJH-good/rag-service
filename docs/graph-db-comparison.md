# FalkorDB vs Apache AGE — 기술 검토 보고서

> **목적**: 하이브리드 Graph RAG 도입을 위한 그래프 DB 선정  
> **대상 시스템**: rag-storage-service (Spring Boot 3.4 / PostgreSQL / Qdrant)  
> **라이선스 조건**: 상업적 배포 가능 (MIT / Apache 2.0)

---

## 1. FalkorDB

### 장점

- **성능**: 인메모리 그래프 엔진으로 복잡한 엔티티 탐색 속도가 빠름
- **Cypher 지원**: Neo4j와 동일한 쿼리 언어 사용 → 레퍼런스 그대로 활용 가능
- **독립 운영**: PostgreSQL과 완전히 분리되어 부하 격리 가능
- **설정 단순**: Docker 컨테이너 하나 추가로 즉시 운영 가능
- **라이선스**: MIT — 상업적 배포 완전 자유

### 단점

- **이중 조회 필요**: 그래프 탐색 결과로 chunk_id 획득 후 PostgreSQL 재조회 — 네트워크 왕복 추가
- **인메모리 한계**: 데이터 증가 시 메모리 비용 증가, 대용량 처리 불리
- **성숙도 부족**: 2023년 RedisGraph 포크로 프로덕션 레퍼런스 적음
- **Java 드라이버**: 공식 지원되나 Spring 생태계 통합 수준 낮음
- **영속성 설정**: 디스크 영속화 별도 설정 필요, 장애 시 데이터 복구 리스크

---

## 2. Apache AGE

### 장점

- **PostgreSQL 통합**: 기존 `rag_chunks`, `rag_documents` 테이블과 **단일 쿼리**로 JOIN 가능
- **인프라 통합**: 기존 PostgreSQL 서버에 extension 추가만으로 운영 — 새 서버 불필요
- **트랜잭션 보장**: PostgreSQL ACID 트랜잭션 내에서 그래프 + 관계형 데이터 함께 처리
- **운영 일원화**: DB 백업·모니터링·장애 대응을 기존 PostgreSQL 운영 방식 그대로 적용
- **라이선스**: Apache 2.0 — 상업적 배포 완전 자유

### 단점

- **성능**: 전용 그래프 엔진 대비 복잡한 그래프 탐색 속도 느림
- **PostgreSQL 부하 공유**: 그래프 연산이 기존 RDB 워크로드와 자원 경합 가능
- **Spring 드라이버 없음**: `JdbcTemplate`으로 raw Cypher 문자열 직접 작성 필요
- **성숙도 부족**: 커뮤니티 규모 작고 복잡한 Cypher 쿼리 지원 불완전한 경우 있음
- **버전 제약**: PostgreSQL 버전과 AGE 버전 호환성 확인 필요

## 4. 현재 프로젝트 적용 시 핵심 차이

### FalkorDB 적용 시 검색 흐름

```
쿼리
 ├─→ Qdrant 벡터 검색         → chunk_id[]
 ├─→ FalkorDB 그래프 탐색     → chunk_id[]   ← 별도 네트워크 호출
 └─→ PostgreSQL chunk_id 재조회              ← 추가 왕복
     → 병합 → 최종 결과
```

### Apache AGE 적용 시 검색 흐름

```
쿼리
 ├─→ Qdrant 벡터 검색
 └─→ PostgreSQL (AGE 포함) 단일 쿼리
      └─ 그래프 탐색 + rag_chunks JOIN → 최종 결과
```

## 5. 선택 기준 요약

| 이런 상황이라면 | 선택 |
|---|---|
| 그래프 탐색 쿼리가 복잡하고 응답속도가 매우 중요 | **FalkorDB** |
| 운영 복잡도를 낮추고 기존 PostgreSQL과 통합 우선 | **Apache AGE** |
| DB 관리 포인트를 하나로 유지하고 싶음 | **Apache AGE** |
| 대용량 데이터 예상, 메모리 비용 부담 | **Apache AGE** |

---

## 6. 최종 권고

현재 프로젝트는 `rag_chunks`, `rag_documents` 등 **PostgreSQL 데이터와 그래프 데이터의 연계 조회**가 필수적이고, 이미 PostgreSQL을 운영 중이므로 **Apache AGE**를 권고합니다.

다만 향후 그래프 규모가 크게 커지거나 탐색 성능이 병목이 된다면 FalkorDB로 마이그레이션을 검토하는 2단계 전략도 유효합니다.
