# 기능 분석 보고서: 벡터 RAG / 의미 청킹 / 그래프 RAG

> 세 가지 구성 시나리오의 동작 방식·강점·한계·적합한 질문 유형을 비교한다.
> 측정값 칸은 골든셋 실측 후 채운다.

---

## 한 줄 요약

| 시나리오 | 구성 | 목표 |
|---|---|---|
| A | 벡터 RAG (고정 길이 청킹, 그래프 없음) | 현재 운영 베이스라인 |
| B | 벡터 RAG + **의미 청킹** (그래프 없음) | 청크 경계 품질 개선 → recall·citation 향상 |
| C | 벡터 RAG + 의미 청킹 + **그래프 RAG** | 연결형·비교 질문까지 커버 |

---

## 1. 시나리오별 파이프라인

### A — 벡터 RAG (고정 길이 청킹)

```
문서 업로드
  → PARSE·CLEAN (PCC)
  → CHUNK : 1200자 고정, 120자 overlap
  → EMBED → Qdrant 적재
  
질문
  → 질문 임베딩 → Qdrant 벡터 검색 → citations → LLM 답변
```

- 청크 경계는 글자 수만 본다.
- 검색은 "의미가 비슷한 청크 찾기" 단계 하나뿐.

---

### B — 벡터 RAG + 의미 청킹

```
문서 업로드
  → PARSE·CLEAN (PCC)
  → CHUNK : 문장 임베딩 → 유사도 breakpoint → 의미 경계 분할
            (max-chars를 모델 토큰 한도 근처까지 상향 조정 — 하드 캡으로만 작동)
  → EMBED → Qdrant 적재
  
질문
  → 질문 임베딩 → Qdrant 벡터 검색 → citations → LLM 답변
```

- 청크 경계가 주제 전환점으로 결정된다.
- 검색 측은 A와 동일; 청크 품질이 올라간 것으로 벡터 recall이 개선된다.
- 그래프 구조 없음 → 여러 청크에 흩어진 관계 정보는 여전히 취약.

---

### C — 벡터 RAG + 의미 청킹 + 그래프 RAG

```
문서 업로드
  → PARSE·CLEAN (PCC)
  → EXTRACT_ENTITY [Pass1] : 엔티티 사전 + 정리본 생성
  → CHUNK : 정리본 위에서 의미 청킹
  → EMBED → Qdrant 적재
  → EXTRACT_RELATION [Pass2] : 관계 추출 → PostgreSQL 그래프
  
질문
  → 질문 임베딩
  → 벡터 검색(Qdrant) + 그래프 탐색(관계 traverse) 병행
  → RRF fusion → citations → LLM 답변
```

- 청크 품질(의미 청킹) + 개념 연결 정보(그래프) 모두 활용.
- Pass1이 정리본을 만들어 주므로, 의미 청킹의 경계 탐지가 더 깨끗해진다.

## 2. 기능 비교

| 기능 | A (벡터) | B (+의미 청킹) | C (+그래프) |
|---|:---:|:---:|:---:|
| 청크 경계 품질 | 낮음 (글자 수 기준) | **높음** (주제 기준) | **높음** |
| 단순 조회 질문 | 가능 | 가능 | 가능 |
| 문서 내 복잡한 질문 | 보통 | **좋음** | **좋음** |
| 연결형·비교 질문 (multi-hop) | 취약 | 취약 | **좋음** |
| citation 문맥 완결성 | 낮음 | **높음** | **높음** |
| 인덱싱 복잡도 | 낮음 | 낮음 | 높음 |
| 인프라 추가 요건 | 없음 | 없음 | PostgreSQL 그래프 테이블, Redis |
| Pass1 LLM 비용 | 없음 | 없음 | 문서당 1콜 |
| 문장 임베딩 비용 | 없음 | PCC 내부 경량 모델 | PCC 내부 경량 모델 |

## 3. 질문 유형별 적합도

### 단순 조회 — "환불 기간이 며칠인가요?"

- **A**: 충분 — 답이 한 청크 안에 들어 있으면 잘 작동한다.
- **B**: 충분 — A와 같거나 더 낫다(청크가 정돈되어 있으므로).
- **C**: 충분 — 그래프 탐색이 추가 비용 없이 소화된다. 대신 그래프 구성 인프라가 필요하다.

### 문서 내 복잡한 질문 — "A 정책의 예외 조건을 모두 정리해줘"

- **A**: 아쉬움 — 예외 조건이 여러 청크에 걸쳐 있으면 일부가 누락될 수 있다. 청크 경계가 예외 설명 중간을 자르는 경우가 흔하다.
- **B**: **좋음** — 예외 설명이 주제 단위로 묶인 청크 안에 온전히 들어가므로 recall이 올라간다.
- **C**: **좋음** — B의 이점 위에 그래프가 보강 역할. 예외 조건이 다른 엔티티와 연결된 경우 그래프 탐색이 추가로 끌어온다.

### 연결형 비교 질문 — "A사 정책과 B사 정책 비교해줘"

- **A**: 취약 — 두 정책의 관련 청크를 각각 찾는 데는 성공해도, 연결 관계를 모르기 때문에 누락이 생기기 쉽다.
- **B**: 취약 — 청크 경계는 개선되지만 문서 간 관계 정보가 없다.
- **C**: **좋음** — 그래프 탐색으로 "A사 → 정책 → 예외" 경로를 따라 흩어진 청크를 모아온다.

## 5. 평가 방법

### 5.1 골든셋 기반 품질 평가 (A/B/C 공통)

**권장 (학생부 기재요령 3-arm UI)** — 벡터 / 그래프·FIXED / 그래프·SEMANTIC을 한 화면에서 비교하고 보고서를 생성한다.

```powershell
.\scripts\serve-chunk-triad-eval.ps1
# http://localhost:8766/  → docs/chunk-triad-eval.html
# 문항: docs/chunk-triad-set.json · 런북: docs/chunk-triad-eval-runbook.md
```

코퍼스: `2026 학교생활기록부 기재요령(초)_F_260219.pdf` (동일 파일을 FIXED·SEMANTIC 카테고리에 각각 인덱싱).

**수능 골든셋 (그래프 vs 벡터 2-arm)**

```bash
scripts/golden-eval.sh          # Linux/macOS
scripts/golden-eval.ps1         # Windows
```

세 시나리오 비교 순서(수동):
1. 현재 설정(A: 고정 청킹, 그래프 disabled)으로 골든셋 실행 → baseline 저장
2. `rag.chunk.mode=SEMANTIC`으로 교체 후 재색인, 골든셋 실행 → B 결과 저장
3. 그래프 RAG(`rag.graph.enabled=true`)까지 활성화 후 재색인, 골든셋 실행 → C 결과 저장

### 5.2 청크 경계 품질 평가 (B·C 추가)

골든셋은 답변 품질을 재지만, 청크 경계 자체의 품질은 직접 재지 않는다. 아래 스크립트로 보완한다.

```bash
scripts/chunk-quality-eval.sh   # 청크 경계 품질 지표 측정
```

측정 항목:
- 청크가 문장 중간에서 끊긴 비율(마지막 문자가 마침표·물음표·느낌표가 아닌 비율)
- 청크 길이 분포 (최솟값·최댓값·평균·표준편차)
- 강제 슬라이스 발생 비율 (응답 메타 또는 크기 추적으로 판단)

## 6. 전환 권고

| 조건 | 권고 시나리오 |
|---|---|
| 단순 조회 중심, 인프라 변경 없이 빠르게 시작 | A |
| 문서 내 복잡한 질문이 많고, 그래프 도입 전 단계적 개선 원함 | **B** |
| 연결형·비교 질문이 핵심 사용사례이고 인프라 투자 가능 | **C** |

> B → C로의 전환은 상호 독립적이다. 의미 청킹(B)은 그래프 RAG 없이도 동작하며,
> 그래프 RAG(C) 도입 시에도 의미 청킹이 정리본 위에서 동작해 경계 탐지 품질이 함께 오른다.
